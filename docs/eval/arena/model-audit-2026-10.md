## 1. Summary

- We checked every current model our three keys can reach. We ran **12 candidates** plus **Claude Opus 5.5 as a quality reference** on 126 labeled images: 94 plated dishes and 32 non-food images. The run cost **$2.86**.
- **No model meets the G2 bar** (precision ≥ 90%, recall ≥ 80%) as scored. Precision is the gap: every model lists some ingredients that the dataset labels leave out.
- **Gemini 3.5 Flash-Lite is the best model within the $500/month cap**, and the cheapest strong one:

  | Precision | Recall | Non-food rejected | $/month at 50K uses | p50 latency |
  |---|---|---|---|---|
  | 88.6% | 90.2% | 96.9% | $28 | 1.1 s |

  It beats the Opus reference on precision and is 6.7 pp behind on recall, at about 7% of the cost.
- **Much of the precision gap comes from how we score, not from the models.** On pizza, models report "tomato sauce", which the eval catalog maps to `ketchup`. Nutrition5k labels pizza as cheese and dough only. If we exclude that one artifact, Gemini 3.5 Flash-Lite clears G2 (92.5% / 90.2%), and Gemini 3.8 Flash gets close (86.0% / 94.5%). That check was done after the run (§7.1), so the official numbers stay as scored until the catalog is fixed and we re-run.
- **OpenAI is the only vendor already approved by Ad Council IT.** Its best options are:
  - **GPT-6 Luna** (effort `none`): 77.3% / 85.9%, $6/month.
  - **GPT-5 mini** (effort `minimal`): 74.2% / 88.3%, $18/month.

  Both trail the Gemini Flash-Lite models by 5–10 pp on F1. Anthropic and Gemini are still waiting on IT acceptance (OPEN-2).
- **Opus 5.5 is a ceiling for recall, not ground truth.** It finds 96.9% of labeled ingredients. Its precision (73.5%) is low because it names plausible extras such as sauce, butter, oil and cheese that the labels leave out.
- **Spending more does not buy accuracy here.** The four most expensive candidates (Sonnet 5.5, Gemini 4 Argon, GPT-6.1 Sol and Gemini 3.8 Flash, $91–$190 a month) all have lower F1 than Gemini 3.5 Flash-Lite at $28. What the higher tiers buy is non-food rejection: every model from Gemini 3.8 Flash up rejects all 32 non-food images.

### 3.1 Opus 5.5 labeling calibration

Art trusts only Opus 5.5 as an image labeler. Before using its labels, we ran a blind test.
- **Method:** Opus labeled 100 random MM-Food images (seed 3244) without seeing the dataset's labels. We then compared its labels with MM-Food's. The pass bar, set before the run, was lenient precision ≥ 0.85 and recall ≥ 0.75, with pantry staples excluded.
- **Result: FAIL.**

  | | Precision | Recall |
  |---|---|---|
  | Strict | 0.626 | n/a |
  | Lenient | 0.715 | 0.747 |
  | High-confidence rows only | 0.825 | 0.815 |

- **Who was right?** In an informal spot check of the disagreements, **Opus was right in roughly half, and MM-Food was right in only about two**. For example, MM-Food labeled a closed takeout bag as "noodles", a flat peach as "apple" and Chinese sausage as "chicken". So the failure says as much about MM-Food's labels as about Opus.
- **Decision for Art:** review `contested-sample.jpg` in the session files, then decide whether to accept Opus's high-confidence labels for future sets.

## 4. Method

### 4.1 Harness

- `pnpm arena` sends every case through the same `extractIngredients` → `matchItems` path the service uses (TDD §7.9):
  - Prompt `p1`.
  - Images downscaled to ≤1 MP in memory.
  - Model output validated with Zod.
  - Results matched to catalog slugs.
- Cases run one at a time.
- There's one run per model, so the report doesn't measure run-to-run variance.

### 4.2 Scoring

- **Precision / recall:** computed over catalog slugs across all cases. A slug the model reports on a non-food image counts as a false positive.
- **Non-food rejected:** the share of the 32 non-food images where the model returned `readable: false`.
- **G2:** precision ≥ 90%, recall ≥ 80%, and every injection case passes (TDD §7.7; the bar itself is still OPEN-8).
- **Forecast:** measured $/call × uses per month, one call per use. "Within cap" means under $500/month for all 12 months.
- **Reference comparison** (new in `efd27b6`): case-by-case, what each candidate misses or wrongly adds compared with the cell marked `"reference": true`.

**What the audit found:**
- **Anthropic adapter fixed (`6b1ea3d`).** Sonnet 5.5, Opus 5.5 and Fable 5.1 reject a forced `tool_choice` with type `tool` or `any`.
  - The adapter now uses structured outputs (`output_config.format: json_schema`).
  - The API rejects `maxItems`, so that one keyword is dropped from the schema we send. Zod still caps results at 60 items.
  - TDD §7.4 is updated.
- **GPT-6.1 Sol** rejects `reasoning_effort: none`. Its lowest setting is `low`.
- **Gemini 3.8 Flash thinks by default.** It averaged about 171 hidden reasoning tokens per call, which are billed as output.
- **Gemini 4 Argon timed out on 8 of 126 calls** at our 15 s model timeout (p95 latency 15.0 s). Those cases count as failures.

## 6. Error analysis

### 6.1 Wrong extras (precision)

| Extra | Reported by | Cause |
|---|---|---|
| `ketchup` | 7–16 times by every model | **Scoring artifact.** Almost all on pizza, where models say "tomato sauce", a synonym of `ketchup` in `eval-v1`. Nutrition5k labels pizza as `cheese` + `pizza-dough` only. |
| `cheese` | 4–10 times | Usually real (a topping, or cheese on a salad). The labels don't always list it. |
| `butter`, `cooking-oil`, `herbs` | Mostly Opus and Sonnet | Plausible cooking ingredients the larger models infer. They aren't visible and aren't labeled. |
| `potato`, `tomato`, `onion`, `cauliflower` | Mostly the GPT nano/mini/Luna models | Mostly real misidentifications. |

### 6.2 Misses (recall)

- `olives`, `egg`, `sausage` and `pizza-dough` are the most common misses for every model. They're usually small or hidden: egg mixed into a dish, sausage under cheese.
- GPT-6.1 Sol missed `pizza-dough` 8 times: it names the dish ("pizza") rather than its parts.

### 7.1 Excluding the `ketchup` / "tomato sauce" artifact

| Model | Precision, scored → adjusted | Recall | Meets G2? |
|---|---|---|---|
| Gemini 3.5 Flash-Lite | 88.6% → **92.5%** | 90.2% | **Yes** |
| Gemini 3.8 Flash | 79.0% → 86.0% | 94.5% | No (precision) |

**The fix is in the catalog, not the models.** Map "tomato sauce" / "pizza sauce" to `tomato` (or a new `tomato-sauce` slug) rather than `ketchup`, add sauce to the pizza labels, and re-run. That costs about $2 and turns these adjusted numbers into official ones.

### 7.2 What the prices assume

- Haiku 5.5's price applies to prompts up to 100K tokens. Ours are about 1.4K.
- Batch pricing (half price) doesn't apply: requests are synchronous.

## 8. Limits of this run

1. **Dishes only.** The run doesn't cover receipts, shopping lists, recipes or fridge photos, so the result may not carry over to the product's main inputs.
2. **No injection cases** in `v1-mixed`. G2 requires a 100% injection pass rate, so this run can't fully confirm G2 for any model.
3. **Small and from one source.** 94 dishes from one US cafeteria (Nutrition5k), so the confidence intervals are wide: ±5–7 pp on precision.
4. **One run per model.** Run-to-run variance isn't measured. Re-run the top 3–4 models 3 times before deciding.
5. **The catalog is a stand-in** (`eval-v1`, 103 slugs), not the CMS catalog (OPEN-8). Synonym choices like the ketchup one move the scores.
6. **Vendor status.** The Anthropic and Gemini keys are ddd's dev/eval keys and used test data only (D25). Neither vendor is approved by Ad Council IT yet (OPEN-2). OpenAI is approved.
